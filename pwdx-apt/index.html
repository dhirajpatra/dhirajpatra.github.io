pwdx apt repository

Stateless, offline password derivation. Debian and Ubuntu (22.04 or newer). Current version: 0.1.0-1.

The screenshot below shows that the apt repository works. A real install over HTTPS from your GitHub Pages address succeeded, apt verified the signature, and pwdx-cli selftest printed selftest ok (spec v1). It ran on Ubuntu “resolute” (26.04), which your output shows.


Install

sudo install -d -m 0755 /usr/share/keyrings
curl -fsSL https://dhirajpatra.github.io/pwdx-apt/pwdx-archive-keyring.gpg | sudo tee /usr/share/keyrings/pwdx-archive-keyring.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/pwdx-archive-keyring.gpg] https://dhirajpatra.github.io/pwdx-apt ./" | sudo tee /etc/apt/sources.list.d/pwdx.list
sudo apt update
sudo apt install pwdx-cli

Then run pwdx-cli selftest. Updates arrive through sudo apt update && sudo apt upgrade.

Verify the signing key

Fingerprint: 3D93F64918CBBD3B580A4418D52F43A7C1D85283

gpg --show-keys --fingerprint /usr/share/keyrings/pwdx-archive-keyring.gpg

Compare it with the fingerprint published in the project README.


How to Use

Use `pwdx-cli get`. Since you installed it with apt, the command is `pwdx-cli`, not `pwdx`. **Once, before your first site:** create your key. Skip this if you already did. ```bash pwdx-cli key new ``` It asks for a key-file passphrase (at least 12 characters). Then back up the file at `~/.config/pwdx/key.pwdxkey` somewhere safe. To use your existing SSH key instead, run `pwdx-cli key import-ssh ~/.ssh/id_ed25519`. **For each site:** run ```bash pwdx-cli get github.com --user you@example.com ``` It asks for two things, and typing is hidden: 1. `Key-file passphrase:` the one you chose when you created the key. 2. `Memorable password:` the short password you remember. It then prints the password for that site. Paste it into the site's sign-up or change-password page. The next time you log in, run the same command with the same inputs, and you get the same password. **What you can change:** ```bash pwdx-cli get github.com --user you@example.com --profile alnum # letters and digits only pwdx-cli get github.com --user you@example.com --length 16 # shorter pwdx-cli get github.com --user you@example.com --counter 2 # new password after a forced change ``` **Copy to the clipboard instead of showing it** (Linux): ```bash pwdx-cli get github.com --user you@example.com | xclip -selection clipboard ``` Install `xclip` with `sudo apt install xclip` if you don't have it. On Wayland, use `wl-copy` instead. **Rules to remember:** - **Use the same inputs every time.** Site, username, counter, type and length must match what you used when you set the password. If you change any of them, you get a different password. Keep a note of any option you changed for a site, such as `--profile alnum`. - **Site spelling:** `github.com` and `https://www.github.com/login` count as the same site. - **No username on a site:** use a fixed placeholder such as `-` every time. - **Different memorable passwords:** if you type the memorable password differently, spaces and capitals included, you get a different password. - **Same results on every device:** copy your key file to your other devices. **Switching an existing account to a pwdx password:** log in to the site as usual, go to its change-password page, and use the new password from the command above. Keep the old one until the site confirms the change. If you get stuck, send me the exact error and what you typed (not your passwords).
