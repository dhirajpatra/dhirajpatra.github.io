pwdx apt repository

Stateless, offline password derivation. Debian and Ubuntu (22.04 or newer). Current version: 0.1.0-1.

The screenshot below shows that the apt repository works. A real install over HTTPS from your GitHub Pages address succeeded, apt verified the signature, and pwdx-cli selftest printed selftest ok (spec v1). It ran on Ubuntu “resolute” (26.04), which your output shows.


Install

sudo install -d -m 0755 /usr/share/keyrings
curl -fsSL https://dhirajpatra.github.io/pwdx-apt/pwdx-archive-keyring.gpg | sudo tee /usr/share/keyrings/pwdx-archive-keyring.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/pwdx-archive-keyring.gpg] https://dhirajpatra.github.io/pwdx-apt ./" | sudo tee /etc/apt/sources.list.d/pwdx.list
sudo apt update
sudo apt install pwdx-cli

Then run pwdx-cli selftest. Updates arrive through sudo apt update && sudo apt upgrade.

Verify the signing key

Fingerprint: 3D93F64918CBBD3B580A4418D52F43A7C1D85283

gpg --show-keys --fingerprint /usr/share/keyrings/pwdx-archive-keyring.gpg

Compare it with the fingerprint published in the project README.


How to Use

Linux

Use pwdx-cli get. Since you installed it with apt, the command is pwdx-cli, not pwdx.

Once, before your first site: create your key. Skip this if you already did.

pwdx-cli key new

It asks for a key-file passphrase (at least 12 characters). Then back up the file at ~/.config/pwdx/key.pwdxkey somewhere safe. To use your existing SSH key instead, run pwdx-cli key import-ssh ~/.ssh/id_ed25519.

For each site: run

pwdx-cli get github.com --user you@example.com

It asks for two things, and typing is hidden:
1. Key-file passphrase: the one you chose when you created the key.
2. Memorable password: the short password you remember.

It then prints the password for that site. Paste it into the site's sign-up or change-password page. The next time you log in, run the same command with the same inputs, and you get the same password.

What you can change:

pwdx-cli get github.com --user you@example.com --profile alnum        # letters and digits only
pwdx-cli get github.com --user you@example.com --length 16            # shorter
pwdx-cli get github.com --user you@example.com --counter 2            # new password after a forced change

Copy to the clipboard instead of showing it (Linux):

pwdx-cli get github.com --user you@example.com | xclip -selection clipboard

Install xclip with sudo apt install xclip if you don't have it. On Wayland, use wl-copy instead.

Rules to remember:

  • Use the same inputs every time. Site, username, counter, type and length must match what you used when you set the password. If you change any of them, you get a different password. Keep a note of any option you changed for a site, such as --profile alnum.
  • Site spelling: github.com and https://www.github.com/login count as the same site.
  • No username on a site: use a fixed placeholder such as - every time.
  • Different memorable passwords: if you type the memorable password differently, spaces and capitals included, you get a different password.
  • Same results on every device: copy your key file to your other devices.

Switching an existing account to a pwdx password: log in to the site as usual, go to its change-password page, and use the new password from the command above. Keep the old one until the site confirms the change.

If you get stuck, send me the exact error and what you typed (not your passwords).

Windows

Both pieces are installed. I'm cross-building the Windows .exe now.

The Windows .exe builds (1.7 MB). To test that it actually runs, I'm installing Wine (a Windows compatibility layer) in the background.

The Windows build runs under Wine and passes its self-test. Now the full flow, with the SSH-key import and password derivation, checked against the independent Python reference.

Yes, the command-line tool works on Windows. I built a Windows version, pwdx-0.1.0-windows-x86_64.zip, which has not run on a real Windows computer yet. I ran it under Wine, a Windows-compatibility layer on Linux, where it passed:

  • Self-test: it printed selftest ok (spec v1).
  • SSH key import and derivation: I imported a real OpenSSH key and derived a password. It exactly matched the independent Python check.
  • Wrong passphrase: a wrong key-file passphrase was rejected.
  • Cross-platform key file: a key file made by the Linux build opened on the Windows build and gave the same Key ID.

Not tested:

  • Real Windows 10 or 11: in particular the hidden password prompt in PowerShell or Command Prompt. My tests fed the passwords in through --stdin.
  • ARM Windows: it is an Intel/AMD 64-bit build.

How to use it on Windows:

  1. Unzip the file anywhere, for example C:\Tools\pwdx. There is no installer.
  2. Open PowerShell in that folder and run .\pwdx.exe selftest, then .\pwdx.exe key new.
  3. Get a password with .\pwdx.exe get github.com --user you@example.com. Add | clip at the end to copy it to the clipboard.

The key file is saved at %APPDATA%\pwdx\key.pwdxkey, and it is the same format as on Linux. You can copy your Linux key file over and get the same passwords. A README with these steps is inside the zip, and I added a Windows section to INSTALL.md.

Windows warnings:

  • SmartScreen: the program isn't code-signed, so SmartScreen may show "Windows protected your PC". Users choose More info, then Run anyway, but only if the SHA-256 checksum matches. I included the checksum file. A signing certificate removes the warning but costs money each year.
  • Antivirus: some antivirus programs flag unsigned command-line tools.
  • Windows Subsystem for Linux (WSL): Windows users can also install Ubuntu there and use your apt package, where the command is pwdx-cli. Its key file lives inside WSL.
